# «Доешь»

Навигатор по холодильнику: пользователь голосом надиктовывает продукты, приложение
подбирает рецепты из локальной базы по совпадению ингредиентов.

Всё работает офлайн и хранится на устройстве: ни бэкенда, ни аккаунтов, ни ключей API.
Единственное обращение наружу — системное распознавание речи Android.

## Запуск

`expo-speech-recognition` — нативный модуль, **в Expo Go не работает**. Нужен dev build:

```bash
npx expo run:android     # первая сборка 10-20 минут, дальше секунды
npm test                 # юнит-тесты разбора речи и подбора рецептов
npx tsc --noEmit         # типы
npm run apk              # релизный APK в android/app/build/outputs/apk/release
```

`android/` не в гите: нативный проект генерируется из `app.json` (Continuous Native
Generation). После правки плагинов или разрешений — `npx expo prebuild --platform android --clean`.

Поэтому список архитектур для релиза живёт в `npm run apk`, а не в `android/gradle.properties`:
собираем только `arm64-v8a` (все телефоны с 2015 года) и `x86_64` (эмулятор). `x86` и
`armeabi-v7a` выкинуты — это минус 38 МБ в APK (115 → 77) и ни одного живого устройства.
Там же `-PreactNativeDevServerIp=127.0.0.1`: без него Gradle-плагин React Native зашивает
в ресурсы релиза локальный IP машины, на которой собирали.

`SYSTEM_ALERT_WINDOW` (рисование поверх чужих окон) шаблон Expo добавляет ради отладочного меню
RN — приложению оно не нужно, поэтому снято через `android.blockedPermissions` в `app.json`.

## Где что лежит

| Файл | За что отвечает |
|---|---|
| `src/data/ingredients.ts` | Справочник продуктов со словоформами. Единственный источник id. |
| `src/data/recipes/` | База из 500 рецептов, по файлу на категорию или партию (каждый меньше 1 МБ). Каждый `ingredientId` обязан быть в справочнике. |
| `src/data/recipe-photos.ts` | Генерируется `scripts/photos/fetch.mjs`: фото блюд, авторы сторонних снимков и подпись набора `PHOTOS_VERSION`. Руками не правится. |
| `scripts/photos/` | Фото блюд: `prompts.mjs` → промпты для генератора, `fetch.mjs` → WebP из `own/`. Запасной путь со стоков: `candidates.mjs` → `pick.mjs`. |
| `assets/recipes/` | Готовые WebP 480×360 без метаданных. `CREDITS.md` появляется, только если есть сторонние снимки. |
| `src/data/shelf-life.ts` | Метки и формат срока годности. Сроков по умолчанию нет. |
| `src/lib/normalize.ts` | Нормализация и грубый стеммер русских слов. |
| `src/lib/ingredient-index.ts` | Обратный индекс словоформ, поиск, подсказки для распознавателя. |
| `src/lib/parse-speech.ts` | Транскрипт → список продуктов. |
| `src/lib/match.ts` | Подбор рецептов по содержимому холодильника и близким срокам. |
| `src/lib/batches.ts` | Партии продукта: срок на часть количества, списание «что испортится раньше». |
| `src/store/fridge.ts` | zustand-стор, persist в AsyncStorage. |
| `src/store/cookbook.ts` | Избранное и история готовок для «Часто готовлю». |
| `src/lib/reminders.ts` | Расписание напоминаний о сроках — чистая функция, покрыта тестами. |
| `src/lib/notifications.ts` | Системные уведомления по этому расписанию: канал, разрешение, планирование. |
| `src/app/` | Экраны expo-router. |
| `assets/icon-src/` | SVG-исходники иконки. PNG в `assets/images/` собираются из них, руками не правятся. |

## Что важно знать, прежде чем менять

**Словоформы перечисляются вручную.** Стеммер в `normalize.ts` — только подстраховка:
беглые гласные его ломают (`яйца → яйц`, но `яиц → яиц`). Добавляя ингредиент,
перечислите реальные падежные формы в `forms`.

**Длина фразы важнее порядка.** Сканер в `parse-speech.ts` пробует окна от длинных
к коротким, поэтому «сливочное масло» выигрывает у «масло», а «болгарский перец» —
у «перец». Добавляя односложную форму, проверьте, не перехватывает ли она многословную.

**Android не ставит запятые.** Разбор не должен зависеть от знаков препинания — в тестах
это зафиксировано отдельным случаем.

**Нераспознанное не выбрасывается.** `parseSpeech` возвращает `unrecognized`, экран
подтверждения показывает эти фрагменты. Молча терять сказанное нельзя.

**Срок живёт у партии, а не у продукта.** Три палки колбасы с разными датами — одна
строка в списке и три партии внутри. По умолчанию срока нет. «Приготовил» списывает
с ближайшей по сроку партии, а если количество не посчитать — убирает одну ближайшую
партию, а не продукт целиком. Меняя форму данных в хранилище, поднимайте `version`
в persist и добавляйте шаг в `migrateFridge`: иначе у пользователей сломается холодильник.

**Скоропортящееся поднимает рецепты.** Рецепт, который использует продукт с меткой
«скоро» (0–3 дня), попадает в раздел «Пора доесть», если готовится сейчас или без одного
продукта. Просроченное рецепты не поднимает — приложение не должно подталкивать готовить
из испорченного. Подъём имеет смысл только потому, что сроки вводит пользователь: пока
их угадывал алгоритм по категории, такой подъём был бы вредным.

**Иконка собирается из SVG.** После правки `assets/icon-src/` выполните `npm run icons`,
затем `npx expo prebuild --platform android --clean` — без второго шага нативный проект
останется со старыми картинками. Масштаб знака на адаптивной иконке (`ADAPTIVE_SCALE`
в `scripts/build-icons.mjs`) рассчитан под нынешнюю форму «Д»: поменяете знак — пересчитайте.

**Напоминания пересобираются целиком.** При любом изменении холодильника `syncReminders`
отменяет все запланированные уведомления и ставит заново по `planReminders`. Не больше одного
в день: в день срока «доешь сегодня», наутро после — «пора выбросить». Разрешение
спрашивается, когда напоминание впервые понадобилось, — после того как у продукта появился срок.

**Рецепт — подробный.** У каждого есть `equipment` (посуда), `steps` не короче четырёх
шагов с количествами, силой огня и признаками готовности, и `tips`. `prep` — что сделать
заранее — по необходимости. Тест в `data.test.ts` проверяет это для всех рецептов и
держит базу ровно в 500 рецептов с уникальными названиями: добавляя рецепт, поправьте
число в тесте. Тексты рецептов — собственные, не копия чужих сайтов.

**Фото блюд — свои и в едином стиле.** Все 500 сгенерированы по одному шаблону промпта
из `prompts.mjs`: меняется только описание блюда, а ракурс, фон и свет общие — иначе
набор снова расползается по стилям, как было со снимками из разных источников.
Исходники PNG 4:3 кладутся в `scripts/photos/own/<id>.png` (папка в `.gitignore`),
`fetch.mjs` сжимает их в WebP и снимает метаданные. Запускайте его без `--force`:
своим снимкам флаг не нужен, а стоковые он заодно перекачает из сети.

**Сменили картинки — кэш сбросится сам, не мешайте ему.** `expo-image` помнит снимок по
номеру ресурса Android, а не по содержимому: добавили файл — номера съехали, и после
обновления к рецепту прилипает чужое блюдо, переустановка не помогает. `fetch.mjs`
пишет в `recipe-photos.ts` подпись набора `PHOTOS_VERSION`, а `use-photo-cache.ts`
при её смене один раз чистит кэш. Правя `recipe-photos.ts` руками, подпись не
обновить — поэтому только через скрипт.

**Запасной путь — Wikimedia Commons.** Только CC0, public domain, CC BY и CC BY-SA
(`commons.mjs` отсекает остальное); выбирает человек по листам превью, потому что поиск
часто находит не то блюдо. Автор и лицензия такого снимка показываются под фото, на
экране «Авторы фото» и в `CREDITS.md` — этого требуют CC BY и CC BY-SA. Поле автора
чистится от e-mail и ссылок: чужие контакты не должны попасть ни в приложение, ни в
репозиторий. Своя картинка в `own/` всегда важнее стоковой.

```bash
node scripts/photos/prompts.mjs             # промпты для генератора в .photo-review/prompts.tsv
node scripts/photos/fetch.mjs               # WebP из own/, recipe-photos.ts, подпись набора
node scripts/photos/candidates.mjs          # стоки: листы превью в .photo-review/
node scripts/photos/pick.mjs borsch=6 uha=-  # стоки: номер снимка или «-», если подходящего нет
```

После правок в `src/data/` и `src/lib/` запускайте `npm test` — разбор русской речи
ломается незаметно.
