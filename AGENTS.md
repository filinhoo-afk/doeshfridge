# «Доешь»

Навигатор по холодильнику: пользователь голосом надиктовывает продукты, приложение
подбирает рецепты из локальной базы по совпадению ингредиентов.

Всё работает офлайн и хранится на устройстве: ни бэкенда, ни аккаунтов, ни ключей API.
Единственное обращение наружу — системное распознавание речи Android.

## Запуск

`expo-speech-recognition` — нативный модуль, **в Expo Go не работает**. Нужен dev build:

```bash
npx expo run:android     # первая сборка 10-20 минут, дальше секунды
npm test                 # юнит-тесты разбора речи и подбора рецептов
npx tsc --noEmit         # типы
```

`android/` не в гите: нативный проект генерируется из `app.json` (Continuous Native
Generation). После правки плагинов или разрешений — `npx expo prebuild --platform android --clean`.

## Что важно знать, прежде чем менять

**Словоформы перечисляются вручную.** Стеммер в `normalize.ts` — только подстраховка:
беглые гласные его ломают (`яйца → яйц`, но `яиц → яиц`). Добавляя ингредиент,
перечислите реальные падежные формы в `forms`.

**Длина фразы важнее порядка.** Сканер в `parse-speech.ts` пробует окна от длинных
к коротким, поэтому «сливочное масло» выигрывает у «масло», а «болгарский перец» —
у «перец». Добавляя односложную форму, проверьте, не перехватывает ли она многословную.

**Android не ставит запятые.** Разбор не должен зависеть от знаков препинания — в тестах
это зафиксировано отдельным случаем.

**Нераспознанное не выбрасывается.** `parseSpeech` возвращает `unrecognized`, экран
подтверждения показывает эти фрагменты. Молча терять сказанное нельзя.

**Срок живёт у партии, а не у продукта.** Три палки колбасы с разными датами — одна
строка в списке и три партии внутри. По умолчанию срока нет. «Приготовил» списывает
с ближайшей по сроку партии, а если количество не посчитать — убирает одну ближайшую
партию, а не продукт целиком. Меняя форму данных в хранилище, поднимайте `version`
в persist и добавляйте шаг в `migrateFridge`: иначе у пользователей сломается холодильник.

**Скоропортящееся поднимает рецепты.** Рецепт, который использует продукт с меткой
«скоро» (0–3 дня), попадает в раздел «Пора доесть», если готовится сейчас или без одного
продукта. Просроченное рецепты не поднимает — приложение не должно подталкивать готовить
из испорченного. Подъём имеет смысл только потому, что сроки вводит пользователь: пока
их угадывал алгоритм по категории, такой подъём был бы вредным.

**Иконка собирается из SVG.** После правки `assets/icon-src/` выполните `npm run icons`,
затем `npx expo prebuild --platform android --clean` — без второго шага нативный проект
останется со старыми картинками. Масштаб знака на адаптивной иконке (`ADAPTIVE_SCALE`
в `scripts/build-icons.mjs`) рассчитан под нынешнюю форму «Д»: поменяете знак — пересчитайте.

**Напоминания пересобираются целиком.** При любом изменении холодильника `syncReminders`
отменяет все запланированные уведомления и ставит заново по `planReminders`. Не больше одного
в день: в день срока «доешь сегодня», наутро после — «пора выбросить». Разрешение
спрашивается, когда напоминание впервые понадобилось, — после того как у продукта появился срок.

**Рецепт — подробный.** У каждого есть `equipment` (посуда), `steps` не короче четырёх
шагов с количествами, силой огня и признаками готовности, и `tips`. `prep` — что сделать
заранее — по необходимости. Тест в `data.test.ts` проверяет это для всех рецептов и
держит базу ровно в 500 рецептов с уникальными названиями: добавляя рецепт, поправьте
число в тесте. Тексты рецептов — собственные, не копия чужих сайтов.

**Фото блюд — со свободными лицензиями и с авторами.** Снимки берутся только с Wikimedia
Commons под CC0, public domain, CC BY и CC BY-SA (`commons.mjs` отсекает остальное).
Выбирает человек по листам превью, а не скрипт: поиск часто находит не то блюдо.
Автор и лицензия показываются под фото и на экране «Авторы фото» — этого требуют
CC BY и CC BY-SA, поэтому фото без записи об авторе в приложение не попадает. Поле
автора чистится от e-mail и ссылок: чужие контакты не должны попасть ни в приложение,
ни в репозиторий. Свои снимки кладутся в `scripts/photos/own/<id>.jpg` (папка в
`.gitignore`), `fetch.mjs` сжимает их и удаляет EXIF с GPS.

```bash
node scripts/photos/candidates.mjs          # листы превью в .photo-review/
node scripts/photos/pick.mjs borsch=6 uha=-  # номер снимка или «-», если подходящего нет
node scripts/photos/fetch.mjs               # WebP, авторы, recipe-photos.ts, CREDITS.md
```

После правок в `src/data/` и `src/lib/` запускайте `npm test` — разбор русской речи
ломается незаметно.
